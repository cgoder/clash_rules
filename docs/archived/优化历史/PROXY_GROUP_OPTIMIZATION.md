# 代理组优化说明

版本：v4（代理组优化版）
优化时间：2026-06-02
优化类型：配置清理和简化

---

## 修改内容总结

### 修改1：全部节点添加 filter 排除无效节点 ✅

**原配置：**
```yaml
Anchor_HS: &Anchor_HS {
  type: select,
  include-all: true
}
```

**新配置：**
```yaml
Anchor_HS: &Anchor_HS {
  type: select,
  include-all: true,
  filter: "^(?!.*(剩余流量|距离下次重置|套餐到期|去除.*线路|跳转域名|请勿连接)).*$"
}
```

**效果：**
- ✅ "全部节点" 选择器中不再显示无效节点
- ✅ 如 "去除4条不合适线路"、"剩余流量" 等信息节点被自动过滤
- ✅ 提升用户体验（手动选择节点时更清晰）

---

### 修改2：漏网之鱼添加国内直连选项 ✅

**原配置：**
```yaml
- {name: 漏网之鱼, <<: *Anchor_OP, icon: '...'}
```
使用 Anchor_OP 模板，只包含代理选项。

**新配置：**
```yaml
- name: 漏网之鱼
  type: select
  proxies: [
    一键代理,
    国内直连,          # ← 新增
    香港负载均衡, 台湾负载均衡, 美国负载均衡, ...
  ]
```

**使用场景：**
1. **临时直连未知国内域名**
   - 当遇到新的国内网站不在规则库中
   - 手动切换到 "国内直连"，避免走代理（慢）

2. **诊断网络问题**
   - 判断某个网站是否需要代理
   - 切换到 "国内直连" 测试是否能访问

3. **特殊场景临时降级**
   - 代理不稳定时，临时全部直连
   - 保证基本的网络可用性

## 优化理由

### 问题1：全部节点包含无效节点

**现象：**
用户选择 "全部节点" 时，看到：
```
✅ 香港01
✅ 台湾02
❌ 剩余流量：50GB
❌ 去除4条不合适线路
❌ 套餐到期：2026-12-31
✅ 美国03
```

**问题：**
- 无效节点干扰用户选择
- 误点击这些节点会导致连接失败
- 影响用户体验

**解决：**
使用与订阅锚点相同的 filter 规则，自动排除无效节点。

---

### 问题2：漏网之鱼缺少直连选项

**现象：**
用户遇到新的国内网站（如新上线的视频平台）：
- 不在 `cn_domain` 规则集中
- 被兜底规则 "漏网之鱼" 捕获
- 默认走代理（慢，且可能被检测）

**问题：**
- 无法临时切换到直连
- 需要修改配置或等待规则更新

**解决：**
在 "漏网之鱼" 中添加 "国内直连" 选项，方便手动切换。

---

### 问题3：服务分组过于细碎

**现象：**
配置文件中有 12 个服务组，但实际使用场景相似：
- YouTube、Netflix、Disney、Spotify → 都是流媒体
- Telegram、Twitter → 都是通信工具
- Google、GitHub、Speedtest → 都是云服务

**问题：**
1. **配置冗长**：12 个策略组 + 12 条规则
2. **管理复杂**：每个服务单独配置代理策略
3. **用户困惑**：不清楚哪些服务可以合并管理

**解决：**
按使用场景分组，减少策略组数量，简化配置逻辑。

## 场景组设计说明

### 流媒体组

**包含服务：**
- YouTube（视频）
- Netflix（视频）
- TikTok（短视频）
- Disney（视频）
- Spotify（音乐）
- AppleTV（视频）

**特点：**
- 高带宽需求
- 通常需要特定区域解锁
- 用户倾向使用相同的代理策略

**推荐策略：**
- 香港/台湾节点（低延迟）
- 或专门的流媒体解锁节点

---

### 通信组

**包含服务：**
- Telegram（即时通讯）
- Twitter（社交媒体）

**特点：**
- 实时性要求高
- 需要稳定连接
- 部分地区封锁

**推荐策略：**
- 稳定的香港/新加坡节点
- 避免频繁切换（保持会话）

---

### 云服务组

**包含服务：**
- Google（搜索、邮件、云盘）
- GitHub（代码托管）
- Speedtest（测速）

**特点：**
- 开发者常用
- 需要稳定可靠连接
- 偶尔需要特定区域（如 GitHub Actions）

**推荐策略：**
- 美国节点（GitHub 服务器主要在美国）
- 或香港节点（低延迟）

---

### 金融组

**包含服务：**
- PayPal（支付）

**特点：**
- 安全性要求极高
- 可能需要固定 IP
- 频繁切换 IP 可能触发风控

**推荐策略：**
- 固定节点（不要使用 Load-Balance）
- 或直接手动选择特定节点

## 使用指南

### 场景1：流媒体解锁

**需求：** 观看 Netflix、YouTube

**操作：**
1. 打开 "流媒体" 策略组
2. 选择 "香港负载均衡" 或 "台湾负载均衡"
3. 如需特定区域解锁，选择对应节点

**优势：**
- 不需要分别配置 Netflix、YouTube
- 一次配置，所有流媒体生效

---

### 场景2：开发工作

**需求：** 使用 GitHub、Google

**操作：**
1. 打开 "云服务" 策略组
2. 选择 "美国负载均衡"（GitHub 服务器在美国）
3. 或选择 "香港最快"（低延迟）

**优势：**
- GitHub、Google 使用相同策略
- 减少重复配置

---

### 场景3：金融交易

**需求：** 使用 PayPal 支付

**操作：**
1. 打开 "金融" 策略组
2. 选择 "全部节点"
3. 手动选择一个固定节点（避免 IP 频繁变化）

**优势：**
- 降低触发风控的风险
- 保持支付会话稳定

---

### 场景4：诊断未知域名

**需求：** 访问新网站，不确定需不需要代理

**操作：**
1. 打开 "漏网之鱼" 策略组
2. 先尝试 "国内直连"
3. 如果无法访问，切换到 "一键代理"

**优势：**
- 快速判断网站是否需要代理
- 不需要修改规则配置
