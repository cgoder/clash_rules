# 保守优化版配置说明

## 修改内容总结

本次优化**只修改了 2 处**，最小化改动风险，专注解决 7x24 稳定运行的核心问题。

---

## 修改1：放宽健康检查参数

**位置：** `Anchor_LB` 锚点（第20-28行）

**修改对比：**
```yaml
# 原配置（激进）
interval: 120              # 2分钟检测一次
timeout: 1500              # 1.5秒超时
max-failed-times: 2        # 2次失败即剔除

# 新配置（保守）
interval: 300              # 5分钟检测一次
timeout: 3000              # 3秒超时
max-failed-times: 5        # 5次失败才剔除
```

**修改理由：**
- 原参数在网络抖动时会大量误判节点故障
- 节点被快速剔除 → 节点池收缩 → 剩余节点压力增大 → 雪崩式失效
- 新参数容忍正常的延迟波动，保持节点池稳定

**影响：**
- ✅ 大幅减少误判，节点池更稳定
- ✅ 减少健康检查频率，降低代理服务器压力
- ⚠️ 真实故障节点的剔除速度从 4 分钟延长到 25 分钟
  - 但在 Load-Balance 模式下，单个故障节点只影响部分连接，可接受

## 修改2：DNS 降级策略

**位置：** `nameserver` 配置（第223-226行）

**修改对比：**
```yaml
# 原配置（纯代理）
nameserver:
  - "https://1.1.1.1/dns-query#一键代理"
  - "https://8.8.8.8/dns-query#一键代理"

# 新配置（混合降级）
nameserver:
  - "https://1.1.1.1/dns-query#一键代理"      # 优先走代理
  - "https://8.8.8.8/dns-query#一键代理"
  - "https://1.1.1.1/dns-query#DIRECT"        # 降级直连备用
  - "https://8.8.8.8/dns-query#DIRECT"
```

**修改理由：**
- 原配置在代理全部故障时，DNS 解析完全失效
- 导致所有国外网站无法访问（ChatGPT/Claude/GitHub 等）
- 新配置允许在代理挂掉时自动降级到直连 DNS

**工作原理：**
1. **正常情况**：前两个 DNS（走代理）正常工作 → 不泄漏
2. **代理故障**：前两个 DNS 超时 → Clash 自动尝试后两个（直连）→ 服务恢复
3. **代理恢复**：Clash 重新使用前两个 DNS → 恢复防泄漏

**影响：**
- ✅ 代理故障时 DNS 解析不中断，国外服务仍可访问
- ✅ 正常运行时仍然防泄漏（优先使用代理 DNS）
- ⚠️ 代理故障期间会泄漏 DNS 查询（权衡：可用性 > 完全防泄漏）

## 技术细节：DNS 降级机制

**Clash DNS 解析顺序：**
```
查询 google.com
  ↓
1. 尝试第一个 nameserver（1.1.1.1 via 代理）
  ├─ 成功 → 返回结果（防泄漏 ✅）
  └─ 失败（超时/代理挂）→ 继续
      ↓
2. 尝试第二个 nameserver（8.8.8.8 via 代理）
  ├─ 成功 → 返回结果（防泄漏 ✅）
  └─ 失败 → 继续
      ↓
3. 尝试第三个 nameserver（1.1.1.1 DIRECT）
  ├─ 成功 → 返回结果（泄漏 ⚠️ 但服务可用）
  └─ 失败 → 继续
      ↓
4. 尝试第四个 nameserver（8.8.8.8 DIRECT）
  ├─ 成功 → 返回结果（泄漏 ⚠️ 但服务可用）
  └─ 失败 → DNS 解析失败 ❌
```

**超时时间：**
- 每个 DNS 查询默认超时 5 秒
- 代理挂时，走完 1→2→3 大约需要 10-15 秒
- 第一次查询慢，后续查询使用缓存（快）

**缓存机制：**
```yaml
cache: {enable: true, size: 4096, expired: 3600}
```
- 成功的 DNS 结果缓存 1 小时
- 即使代理恢复，1 小时内仍使用缓存结果（不会重新泄漏）
