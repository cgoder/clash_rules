## 剩余的 14 条警告

### 警告内容

**全部是 DIRECT DNS 连接超时：**
```
[TCP] dial DIRECT mihomo --> 1.1.1.1:443 error: 
  dial tcp 1.1.1.1:443: connectex: 
  A connection attempt failed because the connected party 
  did not properly respond after a period of time
```

### 警告分析

**这些是正常的降级尝试：**

1. **触发条件：**
   - 当代理 DNS 查询超时时
   - Clash 尝试降级到 DIRECT DNS
   - 尝试直连 1.1.1.1:443 和 8.8.8.8:443

2. **失败原因：**
   - 你的网络环境中，1.1.1.1:443 和 8.8.8.8:443 被封锁
   - 直连超时（不是 Clash 的问题）

3. **实际影响：**
   - **无影响**
   - 因为代理 DNS 是优先级更高的选项
   - 代理 DNS 成功时，根本不会尝试 DIRECT DNS

## 建议优化（可选）

### 如果想消除这 14 条警告

**方案1：移除 DIRECT DNS 降级（推荐）**

```yaml
nameserver:
  - "https://1.1.1.1/dns-query#一键代理"
  - "https://8.8.8.8/dns-query#一键代理"
  # 删除这两行（因为直连被封锁，尝试也没用）
  # - "https://1.1.1.1/dns-query#DIRECT"
  # - "https://8.8.8.8/dns-query#DIRECT"
```

**理由：**
- 你的网络环境下，1.1.1.1/8.8.8.8 直连不可用
- 保留降级选项只会产生无意义的警告
- 移除后日志会更干净

**权衡：**
- ⚠️ 如果所有代理节点全挂，DNS 完全失效
- ✅ 但这种情况极少见
- ✅ 日志更干净，不会误导

---

**方案2：default-nameserver 添加国内 DNS**

```yaml
default-nameserver:
  - 1.1.1.1
  - 223.5.5.5  # 添加国内 DNS 备用
```

**理由：**
- 如果 1.1.1.1 无法直连，回退到国内 DNS
- 提高 DoH 服务器域名的解析成功率

**权衡：**
- ⚠️ 可能泄漏初始 DNS 查询（DoH 服务器域名）
- ✅ 提高系统稳定性
